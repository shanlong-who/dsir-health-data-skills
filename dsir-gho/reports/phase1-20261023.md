## Causes and fixes

1. **Different catalogue coverage.** Fresh successful catalogue retrievals found
   3,102 legacy codes and 937 xMart codes: 229 shared, 2,873 legacy-only and
   708 xMart-only. These are dated catalogue observations, not measures of
   retrievable data or statistical equivalence. The default now matches DSIR:
   legacy. Existing callers needing xMart must pass `--backend xmart` explicitly.
2. **Wrong legacy pagination default.** The old global 5,000-row page exceeded
   legacy's observed 1,000-row limit. Defaults are now backend-specific:
   legacy 1,000, xMart 5,000. Oversized legacy pages fail before networking.
3. **Incorrect source labels.** Search and legacy metadata previously constructed
   URLs from an xMart constant. Results now identify their selected catalogue,
   backend and evidence. xMart retrieval metadata uses the chosen directory
   route's name and unit rather than another entry sharing the code.
4. **Overly narrow indicator syntax.** Valid numeric/dotted catalogue codes such
   as `2017_AH_6.3` were rejected before lookup. Safe numeric/dotted codes now
   pass syntax validation and still require catalogue confirmation.
5. **Invalid dimensions could look empty.** Legacy validates observed position
   types against live vocabularies. xMart checks observed codes and source
   vocabularies. Invalid sibling codes cannot hide behind valid selections.
   Unverifiable xMart codes produce `unverified_dimension`, never an assertion
   of missing observations. Requested filters are never silently removed.
6. **Failure evidence.** The compatible `who_api_request_failed` code now adds a
   reason for request parameters, temporary HTTP failures, network errors and
   other HTTP responses. Catalogue absence is scoped to the verified backend.
   Unsupported public routes remain distinct. Legacy empty-baseline probes now
   require consistent counts; missing or duplicate observation IDs fail retrieval.

The existing adapters, commands, core 15-column schema, cleaning, location
resolution, raw exports and checksums are retained. No provider framework,
database, remote service or new runtime dependency was introduced. Historical
source hashes and test reports remain historical evidence.

## Backend policy and acceptance criteria

Legacy default improves access to the legacy catalogue and matches released
DSIR. Explicit xMart preserves access to its different coverage and dimensions.
Automatic fallback was evaluated and left disabled: absence from a verified
catalogue is materially different from no matching observations, invalid filters,
HTTP failure or incomplete retrieval. Source releases and definitions are not
automatically equivalent. A future opt-in policy would require prior explicit
authorization, exact target code verification, target dimension validation, both
attempts recorded, and separately labelled results. It must never splice sources.
See [backend comparison](../references/backend_comparison.md).

Acceptance requires working defaults and explicit selection; correct distinction
of absence, empty selections, invalid parameters and failures; source-specific
country/year/sex/age filters; preserved missing values and provenance; passing
offline regressions and bounded fresh live checks. All automated Phase 1 checks
below passed. User-facing plugin acceptance remains a separate manual gate.

## Remaining limits and manual acceptance

- No equality of releases, definitions or values across backends is established.
  Compare only separately reviewed selections; do not fill one backend's gaps
  with the other. Retrieval timestamps are not release identifiers.
- Live checks are deliberately small. They do not validate all catalogue routes,
  every dimension combination, rare territories, all regional variants or every
  client environment. Reference metadata can be incomplete; unverifiable filters
  fail explicitly and may need source-specific investigation.
- No published ZIP was rebuilt, version bumped or marketplace updated. Local
  packaged source is synchronized, but the older packaging script reads a ZIP:
  a future reviewed release must build from the repaired source first.
- Maintainer acceptance: in an authorized local test installation, request
  Philippine measles with no backend specified; DTP3 with explicit xMart; and an
  age/sex-filtered query. Confirm the assistant states the backend, retains
  requested dimensions, delivers CSV with JSON/raw evidence, explains empty
  results and failures, and never substitutes or combines sources. Changing or
  publishing the installed plugin requires a separate instruction.

The local engineering criteria for Phase 1 are met. Enter Phase 2 only after
the maintainer accepts this candidate and explicitly requests GHE work.
